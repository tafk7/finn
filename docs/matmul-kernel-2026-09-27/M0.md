## Q4: per-channel folding

- FinnLib refuses VVU on anything but DSP58 (`dotp_axi.sv:78-83`), and only the
  INT8 core takes unbroadcast activations (`:263`). Baseline FINN's RTL VVAU is
  also DSP58 only (`vectorvectoractivation_rtl.py:252-266`).
- The INT8 core packs three SIMD lanes per DSP58 and chains `ceil(SIMD/3)` of
  them per PE (`dotp_8sx9_dsp58.sv:59`); PE and SIMD are otherwise free. PE
  divides the channels and SIMD the window, as in baseline FINN
  (`vectorvectoractivation.py:237-258`). No baseline RTL folding is lost.
- Baseline FINN's RTL VVAU never pumps compute (`$PUMPED_COMPUTE$ = 0`).
  `dotp_axi`'s pumped path is written for both modes; the per-channel sweep
  exercises it, and it is refused if it fails.
- Baseline HLS VVAU (other targets, `resType=lut`) is not covered: flagged
  future work.

## Q5: the per-channel activation order

Baseline FINN reshapes the SWG's depthwise output `(1, H, W, K·C)` directly
into beats of `SIMD·PE` consecutive elements (`vectorvectoractivation.py:237-258`
with the reshape in `vectorvectoractivation_rtl.py:67-72`), and FinnLib reads
lane `s·PE + p` as window element `s`, channel `p` (`dotp_axi.sv:109-119`). So
the stream is declared as a traversal of the operand `(R, K, C)` (window major,
channel fastest):

- beats: row, channel fold (`C/PE`), window fold (`K/SIMD`);
- lanes: SIMD window elements (stride `C`), then PE channels (stride 1),
  channel fastest.

The weights are `tile(C, K, PE, SIMD)`, the same walk as the dense case with
`C` in place of `N`; results are `(R, C)` in PE lanes.

## Q7: the port relation

Both contractions are checked by one labelled relation instead of two
hand-written ones. Each operand's axes carry index labels: dense `X[r,k]`,
`W[n,k]`, `Y[r,n]`; per-channel `X[r,k,c]`, `W[c,k]`, `Y[r,c]`; `k` is reduced.

1. Each port's lanes are the loops dotp reads (activation SIMD along `k`, and
   PE along `c` when not broadcast, `c` fastest; weights PE rows of SIMD `k`;
   results PE along `n` or `c`).
2. Beat by beat, activation and weight walks agree on every index they share.
3. Within a frame (the activation marker period) only `k` moves.
4. Frame by frame, each result index follows the operand that carries it.

This remains the stopgap D10 replaces.
